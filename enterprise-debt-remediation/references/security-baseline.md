# 安全基线

安全、数据、发布、回滚能力是企业级最低门槛。没过这些门槛时，不要把项目判为企业级。

## P0 停止条件

发现以下任一情况，优先停止扩展性和 UI polish 工作：

- 可确认的认证绕过、越权、敏感数据泄露
- 明文 token、私钥、生产凭据进入仓库或日志
- 用户数据可能被破坏、覆盖、误删且没有可靠恢复
- 发布或迁移可能不可回滚
- 核心链路存在高频失败且没有告警
- 依赖存在已知高危漏洞且暴露在可触达路径

## P1 安全门槛

- 认证和授权逻辑集中、可审计
- 敏感配置不进入源码、日志、前端包和错误响应
- 外部输入有校验、转义或白名单
- 关键操作有审计日志
- 依赖有锁文件和漏洞巡检
- 数据有分级、脱敏、保留、删除策略
- 发布、回滚、迁移有可验证路径

## 审计证据

优先检查：

- 环境变量、配置文件、示例配置、CI secret 用法
- 鉴权中间件、路由守卫、权限判断
- API 输入校验、文件上传、URL 拼接、SQL/命令执行
- 日志、错误处理、审计记录
- 依赖清单、锁文件、安全扫描结果
- 数据迁移、备份、恢复和回滚脚本

## 修复原则

- 先封住可利用路径，再做结构优化。
- 先隐藏或轮换泄露凭据，再补扫描规则。
- 先补关键日志和告警，再扩大重构。
- 先给高风险路径加测试，再抽象公共能力。
